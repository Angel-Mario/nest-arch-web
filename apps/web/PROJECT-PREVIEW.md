# Project explorer

The landing page and terminal summary open an explorer of the real generator's initial files. The engine and Handlebars templates live in `private/nest-arch`, outside `public`, and are imported only by the server. The preview never installs packages, runs project code, initializes Git, or fetches agent skills. Migrations and files generated by external setup tools remain setup steps in the generated README.

## Synchronizing a release

For the complete npm release procedure, private repository access and automatic GitHub Actions setup, see the [maintainer release guide](../../docs/NEST-ARCH-RELEASES.md). The workflow prepares a validated snapshot PR; the npm version badge still follows its separate Convex cron.

Run `pnpm --filter web preview:sync` with `C:/VS/nest-arch` alongside this repository. For a different location, run `pnpm --filter web preview:sync /path/to/nest-arch`. Commit the private runtime, templates, generated manifest, and versioned preset JSON together. Deployments build from this snapshot and do not need access to the generator repository.

The identity includes the CLI version plus a SHA-256 digest of the core sources, shared sources, templates, dependency reference, option catalog, and preview adapter. Changing those inputs selects a new cache namespace even without changing the CLI's version. Do not modify a snapshot in place. Old versioned assets may be removed in a later release after their cache lifetime has elapsed.

Six starter configurations are pregenerated during synchronization and served directly from `/project-previews/<version>/<hash>.json`. Visiting these presets does not invoke a generation function. Clicking Explore is the only action that fetches a preview. Opening files, searching, copying and renaming remain local. The browser also reuses successful responses and coalesces concurrent requests.

Syntax highlighting runs in the browser using Shiki's JavaScript engine and a limited set of grammars. It follows the light/dark theme and falls back to plain text if highlighting fails. Line numbers are decorative and are excluded from copied source. Material Icon Theme SVGs are served locally, including its NestJS icon-pack colors. The source attribution and MIT license are in `public/material-icons`.

## Persistent cache

For on-demand previews on Vercel, connect a **public Vercel Blob store** and set its server-only `BLOB_READ_WRITE_TOKEN`. Generated JSON contains only template/example data and a fixed project-name marker; neither user names nor server environment variables are saved. Only rendered projects are public, not generator sources or templates.

Each GET uses the artifact version and canonical configuration hash. The route canonicalizes query strings, validates inputs and certified combinations, reads Blob before generating, and stores successful results under a versioned deterministic pathname. HTTP responses use immutable browser caching and Vercel CDN caching. A CDN hit avoids the function; a Blob hit still invokes the function but avoids regeneration. In-process promise sharing prevents duplicate concurrent work within one instance. Separate instances can still race on a first miss; their deterministic results use the same Blob pathname. Blob storage, operations and bandwidth still incur usage.

Without a Blob token in production, on-demand previews return 503 and the UI offers the static presets. This prevents accidental uncached generation costs. Local development uses `.cache/project-previews` on disk, preserving previews across process restarts. No database or production storage is created automatically.

Project names and their camel/Pascal/underscore variants are substituted locally. Array selections are deduplicated and sorted; unused Ultracite preferences do not affect identity. Creation timestamps use a visible placeholder. Preview Git/dependency installation metadata is fixed to `false`, as neither step runs. Failed requests are not cached. Outdated artifact versions return 409 so the user can reload.

## Verification

Run `pnpm --filter web test:preview` and `pnpm --filter web check-types`. Tests cover canonicalization, version invalidation, restart persistence, concurrent misses, retry behavior, unsupported combinations, static presets and equivalence with real generator output including programmatic auth files.
